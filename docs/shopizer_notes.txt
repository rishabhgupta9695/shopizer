1. WHAT IS SHOPIZER?
=============================================================
Shopizer is a Java-based open-source headless e-commerce platform.
It exposes a REST API for catalog, cart, checkout, orders, customers,
merchants, users, content, shipping, tax, and more.

The backend is a Spring Boot application. The frontend is separate
(React shop + Angular admin panel - both in sibling repos).

=============================================================
2. PROJECT MODULE STRUCTURE
=============================================================
shopizer/                    <- root Maven multi-module project
  sm-core-model/             <- JPA entities / domain model (no Spring)
  sm-core-modules/           <- pluggable integration modules (payment, shipping, search)
  sm-core/                   <- core business services (Spring services, DAOs)
  sm-shop-model/             <- REST API request/response DTOs (ReadableXxx / PersistableXxx)
  sm-shop/                   <- Spring Boot web app (controllers, facades, security, config)

Build order (Maven resolves automatically):
  sm-core-model -> sm-core-modules -> sm-core -> sm-shop-model -> sm-shop

=============================================================
3. PREREQUISITES
=============================================================
- Java 11 or 17 (tested on both)
- Maven 3.6+ (or use included ./mvnw wrapper)

Optional (for MySQL instead of embedded H2):

=============================================================
4. BUILD THE APPLICATION
=============================================================

Step 1: Clone the repo
  git clone https://github.com/shopizer-ecommerce/shopizer.git
  cd shopizer

Step 2: Build all modules from root
  ./mvnw clean install
  (or: mvn clean install)
  (add -DskipTests to skip tests: ./mvnw clean install -DskipTests)

Step 3: Run the Spring Boot app
  cd sm-shop
  ../mvnw spring-boot:run
  (or from root: ./mvnw spring-boot:run -pl sm-shop)

The app starts on: http://localhost:8080
Swagger UI:        http://localhost:8080/swagger-ui.html

=============================================================
5. DEFAULT DATABASE (H2 - no setup needed)
=============================================================
By default, Shopizer uses an embedded H2 database.
The H2 file is stored at: sm-shop/SALESMANAGER.h2.db
Schema name: SALESMANAGER
hibernate.hbm2ddl.auto=update  (auto-creates/updates tables)

On first run, InitializationLoader seeds reference data
(countries, zones, currencies, languages, default merchant store).

=============================================================
6. SWITCHING TO MYSQL
=============================================================
Step 1: Create the database and user in MySQL:
  CREATE DATABASE SALESMANAGER;
  CREATE USER shopizer IDENTIFIED BY 'your-password';
  GRANT ALL ON SALESMANAGER.* TO shopizer;
  FLUSH PRIVILEGES;

Step 2: Edit sm-shop/src/main/resources/profiles/local/database.properties
  db.jdbcUrl=jdbc:mysql://127.0.0.1:3306/SALESMANAGER?autoReconnect=true&useUnicode=true&characterEncoding=UTF-8
  db.user=shopizer
  db.password=your-password
  db.driverClass=com.mysql.cj.jdbc.Driver
  hibernate.dialect=org.hibernate.dialect.MySQL5InnoDBDialect
  hibernate.hbm2ddl.auto=update

Step 3: Run with the local profile:
  cd sm-shop
  ../mvnw spring-boot:run -Dspring-boot.run.profiles=local

9. SECURITY & AUTHENTICATION
=============================================================
Shopizer uses JWT (JSON Web Tokens) for authentication.
There are two separate security realms:

  a) ADMIN / USER realm  -> /api/v1/private/**
     Login: POST /api/v1/private/login
     Body: { "username": "admin@shopizer.com", "password": "password" }
     Returns: { "token": "Bearer <jwt>" }
     Use header: Authorization: Bearer <token>

  b) CUSTOMER realm -> /api/v1/auth/**
     Login: POST /api/v1/customer/login
     Body: { "username": "customer@email.com", "password": "password" }
     Returns: { "token": "Bearer <jwt>" }

URL patterns:
  /api/v1/private/**  -> requires ADMIN JWT
  /api/v1/auth/**     -> requires CUSTOMER JWT
  /api/v1/**          -> public (no auth)
  /services/**        -> legacy v0 endpoints

Default admin credentials (seeded on first run):
  Username: admin@shopizer.com
  Password: password

Security config class: MultipleEntryPointsSecurityConfig.java
JWT utility: JWTTokenUtil.java
Token filter: AuthenticationTokenFilter.java

=============================================================
12. CORE DOMAIN ENTITIES (sm-core-model)
=============================================================
All entities extend SalesManagerEntity<ID, T> which provides
the base JPA entity structure with audit fields.

--- MERCHANT / STORE ---
MerchantStore          - The store entity (code, name, currency, country, etc.)
MerchantConfig         - Key-value config for a store
MerchantConfiguration  - Typed configuration (payment, shipping, etc.)
MerchantLog            - Audit log for merchant actions

--- CATALOG / PRODUCT ---
Product                - Core product entity
  - Has: ProductAvailability (stock, price per region)
  - Has: ProductDescription (i18n name, description, SEO url)
  - Has: ProductImage (images)
  - Has: ProductAttribute (option values assigned to product)
  - Has: ProductRelationship (related/featured products)
  - Has: ProductReview (customer reviews)
  - Has: ProductType (type classification)
  - Has: Manufacturer (brand)
  - Has: Category (one or more categories)
  - Has: TaxClass

ProductAvailability    - Stock quantity, price, region availability
ProductPrice           - Price with optional special price and dates
ProductDescription     - i18n descriptions (name, description, friendlyUrl, tags)
ProductImage           - Image file reference
ProductAttribute       - Links product to a ProductOptionValue
ProductOption          - Option definition (e.g. "Color", "Size")
ProductOptionValue     - Option value (e.g. "Red", "XL")
ProductOptionSet       - Set of options grouped together
ProductType            - Product type (GENERAL, DIGITAL, etc.)
ProductReview          - Customer review with rating
Manufacturer           - Brand/manufacturer entity
Category               - Hierarchical category tree
  - CategoryDescription (i18n)
Catalog                - Named catalog grouping products
CatalogCategoryEntry   - Entry linking a product to a catalog

--- PRODUCT VARIANTS (newer model) ---
ProductVariant         - A specific variant of a product (SKU-level)
ProductVariantGroup    - Groups variants together
ProductVariation       - Variation definition (e.g. size+color combo)

--- CUSTOMER ---
Customer               - Customer account
  - Billing (embedded billing address)
  - Delivery (embedded delivery address)
  - CustomerAttribute (custom attributes)
CustomerOption         - Custom option for customer profile
CustomerOptionValue    - Value for customer option
CustomerReview         - Review written by a customer
CustomerOptin          - Newsletter/optin subscription

--- ORDER ---
Order                  - The main order entity
  - OrderProduct (line items)
  - OrderTotal (subtotal, tax, shipping, grand total)

13. ARCHITECTURE PATTERNS
=============================================================

Request Flow:
  HTTP Request
    -> Spring Security Filter (JWT validation)
    -> API Controller (v1/v2 in store/api/)
    -> Facade (store/facade/ or store/controller/*/facade/)
    -> Core Service (sm-core business services)
    -> Repository (JPA/Hibernate)
    -> Database

Key patterns:
  - Persistable* DTOs: incoming request bodies (create/update)
  - Readable* DTOs: outgoing response bodies
  - Populator: converts between entity <-> DTO (older pattern)
  - Mapper: MapStruct-based entity <-> DTO (newer pattern)
  - Facade: orchestration layer between controller and services

Package layout in sm-shop:
  store/api/v1/         <- REST controllers (API endpoints)
  store/api/v2/         <- REST controllers (newer endpoints)
  store/facade/         <- Facade implementations
  store/controller/*/facade/  <- More facade implementations (older)
  store/security/       <- JWT, auth managers, filters
  application/config/   <- Spring configuration classes
  populator/            <- Entity <-> DTO converters (older)
  mapper/               <- MapStruct mappers (newer)
  model/                <- DTO classes (request/response)
  utils/                <- Utility classes

14. HOW TO ADD NEW FUNCTIONALITY
=============================================================

To add a new feature (e.g. "Wishlist"):

1. Add entity in sm-core-model:
   - Create entity class in com.salesmanager.core.model.*
   - Extend SalesManagerEntity<Long, Wishlist>
   - Add JPA annotations (@Entity, @Table, etc.)

2. Add repository in sm-core:
   - Create interface extending SalesManagerRepository<Wishlist, Long>
   - Add custom query methods if needed

3. Add service in sm-core:
   - Create interface: WishlistService
   - Create implementation: WishlistServiceImpl
   - Annotate with @Service, inject repository

4. Add DTOs in sm-shop-model (or sm-shop):
   - PersistableWishlist (request body)
   - ReadableWishlist (response body)

5. Add mapper/populator in sm-shop:
   - Create mapper or populator for entity <-> DTO conversion

6. Add facade in sm-shop:
   - Create WishlistFacade interface
   - Create WishlistFacadeImpl with business logic

7. Add API controller in sm-shop:
   - Create WishlistApi.java in store/api/v1/
   - Annotate with @RestController, @RequestMapping("/api/v1")
   - Inject facade, define endpoints

8. Rebuild:
   ./mvnw clean install -DskipTests
   cd sm-shop && ../mvnw spring-boot:run

15. IMPORTANT NOTES & GOTCHAS
=============================================================

1. Multi-store: Shopizer supports multiple stores. Most endpoints
   accept a "store" query param (defaults to "DEFAULT").
   The MerchantStore is resolved via MerchantStoreArgumentResolver.

2. i18n: Most entities have a *Description companion entity for
   internationalized text. The "lang" query param (e.g. ?lang=en)
   controls which language is returned.

3. URL pattern for auth:
   - /private/** = admin JWT required
   - /auth/** = customer JWT required
   - everything else = public

4. Default store code: "DEFAULT"
   Default admin: admin@shopizer.com / password

5. H2 console: Not enabled by default. To enable, add to
   application.properties:
     spring.h2.console.enabled=true
     spring.h2.console.path=/h2-console

6. Swagger UI is the best way to explore all endpoints:
   http://localhost:8080/swagger-ui.html

7. Actuator endpoints are exposed at /actuator/**
   Health: http://localhost:8080/actuator/health

8. Image uploads are stored locally under sm-shop/files/
   (configurable via shopizer-properties.properties)

9. Elasticsearch is optional. Set INDEX_PRODUCTS=false in
   shopizer-properties.properties to disable search indexing.
   management.health.elasticsearch.enabled=false is already set.

10. The CORS filter (CorsFilter.java) allows all origins by default.
    Tighten this for production.

11. XSS protection is applied via XssFilter.java on all requests.

12. Bean definition overriding is enabled:
    spring.main.allow-bean-definition-overriding=true
    This allows modules to override default implementations.

13. Multipart limits:
    max-file-size=4MB, max-request-size=10MB
    Increase in application.properties if needed.

14. The sm-core-modules module contains pluggable integrations:
    - Payment: PayPal, Stripe, etc.
    - Shipping: Canada Post, flat rate, etc.
    - Search: Elasticsearch
